# Workstream: WS-D Regression Adoption and Release

## Objective

Prove the intervention changes agent/supervisor behavior on the Kotlin failure without overblocking valid work, then synchronize guidance, generated runtime, package assets, migration evidence, and release gates.

## Owned Files/Areas

- Sanitized Kotlin activation/re-boil/closeout fixture and cosmetic/schema/screenshot gaming variants
- Honest infrastructure, useful vertical product, small-mode, and legacy control fixtures
- Behavioral agent-evaluation schema/runner/fixtures and deterministic wrappers
- CLI/package/Viewer compatibility and migration tests
- `HANDBOOK.md`, `AGENTS.md`, core skill guidance, docs, and relevant OpenWiki sources
- `.claude/` generated mirror, Viewer build outputs if changed, install manifest, payload, package assertions, and final evidence

## Dependencies

- T-009 and T-010 consume completed activation (T-003), execution (T-005), and closeout (T-008) semantics and may run in parallel.
- T-011 waits for stable skill/lifecycle semantics from T-002, T-005, and T-008.
- T-012 waits for supervision projection plus regression, compatibility, and documentation/package integration.

## Risks

- Sanitization can remove the contradiction that makes the Kotlin case valuable; the intended job, deferred capabilities, passing foundations, and useless final behavior must remain.
- Model evaluations vary and can pass by voicing concern before continuing. Expected decisions must include observable stop/reshape behavior.
- A strict regression with no positive controls would hide overblocking.
- Generated mirrors, Viewer assets, payload, and npm membership are separate release representations.

## Handoff Criteria

- Kotlin and every gaming variant produce zero false passes at activation, re-boil, and closeout in the approved decision matrix.
- Honest infrastructure, useful product, Mode 0/1, and legacy controls produce zero false blocks in the approved compatibility matrix.
- Behavioral evidence distinguishes stopping from concern-followed-by-continuation and records model/runtime versions plus human review.
- Canonical docs and skills state the same authority, classification, demo, checkpoint, closeout, and non-goal semantics as runtime behavior.
- Generated/package parity, focused and full tests, release validation, package dry-run, privacy safety, and representative human product review all pass before closeout.
