# Research Plan: User value gate and product quality design

## Goal

Determine the smallest mode-scaled intervention that would have stopped or reshaped the failed Kotlin foundation project while preserving honest infrastructure, light small modes, and Delano's existing source-of-truth model.

## Primary Question

What mode-scaled contract, lifecycle, supervision, product-review, and evaluation design would have stopped or reshaped the failed Kotlin foundation project without banning legitimate infrastructure or burdening small changes?

## Scope

### In Scope

- Read the complete specified T3 Code session and its six screenshots.
- Inspect Delano's handbook, modes, templates, validators, skills, lifecycle commands, closeout flow, Viewer/review boundaries, evaluation fixtures, and completed strategy-layer precedent.
- Inspect Matt Pocock's public skill sources for concise, confrontational, action-oriented patterns.
- Compare artifact-only, lifecycle, behavioral-evaluation, and human-review enforcement options.
- Fold durable conclusions into the planned spec, decisions, plan, workstreams, and tasks.

### Out of Scope

- Runtime implementation or a production prototype.
- Copying raw private session messages, local paths, or screenshots into repository artifacts.
- Changing the frozen Kotlin application.
- Remote tracker mutation or public action.

## Decisions Made

| Decision | Rationale |
| --- | --- |
| Use existing canonical artifacts rather than mandatory `payoff.md` | Avoids a parallel truth source and makes the intervention part of activation, planning, execution, and closeout. |
| Combine deterministic gates, short skills, behavioral evals, and human review | Current conformance checks cannot judge whether a user can do the job; no single replacement check can either. |
| Keep product, mixed, and infrastructure branches explicit | Preserves valuable invisible work while preventing it from being reported as immediate user payoff. |
| Track executable demo steps instead of artifact/task volume | The Kotlin project had abundant artifacts and evidence but no supervision capability. |
| Re-boil at value-risk boundaries and on scope mismatch | Creates a stop-loss where supervisors currently route around foundation blockers; avoids arbitrary task/time quotas. |
| Make Kotlin a three-stage regression with control cases | Proves activation, supervision, and closeout behavior and measures both false passes and false blocks. |
